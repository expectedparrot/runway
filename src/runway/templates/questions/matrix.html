The reference does not choose between a table and a stacked list on the server -- it renders both and lets a breakpoint decide, so a respondent turning a phone sideways mid-question keeps their answer. `.edsl-matrix-stack-view` and `.edsl-matrix-table-view` are the two halves, and a survey's own CSS flips them. The two views therefore cannot share radio names: one name is one group, and the hidden view's radio would uncheck the one on screen. The stacked list scopes both its ids and its group names under `_stack`, and every id on both sides is built from indices rather than from row and column text -- a row piped from a scenario file reads "", and an id may not contain whitespace. The empty header cell is empty in the reference too: the row-label column has no heading, and that space is what lets the option headings sit over their own columns. Class strings are inline rather than passed in, so this file can be diffed against the reference component side by side; a class string in a .py file is invisible to the stylesheet build, which scans templates and would drop the rules for it. The empty-comment separator lines exist only to suppress whitespace between literal elements; JSX discards that whitespace, so emitting it would break byte parity. See README.
