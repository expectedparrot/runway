{# Transcription of the reference implementation's third matrix layout: one row at a time, which a humanize schema asks for with `format: {type: carousel}`. The grid is what a matrix is for -- every row on one screen against a shared scale -- and that is also what breaks it on a narrow screen. This spends the overview to buy the room back: the row rides in a carousel, and the options answering it sit below at full width. **What is recorded here is the resting state.** The reference drives this with a carousel library that does nothing at all on the server: no effect runs, so the first slide is the current one, the previous arrow is disabled and the status reads "1 of N". That is what a golden captures and what this file emits. Moving between rows is the page script's job -- see `carousel.html`, and README under Known gaps for what it does not do. Every row is emitted, because that is what the reference emits: the slides are how the carousel has something to scroll to. Only the row on screen is left out of `aria-hidden`, so a respondent meets one row at a time whichever way they are reading. Only the *first* row's options are here, though, and that is the reference's shape rather than an economy: the option list sits outside the carousel and is re-rendered for whichever row is showing, so on the server there is exactly one.
