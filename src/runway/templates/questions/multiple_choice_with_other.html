{# Transcription of the reference implementation's multiple choice with other: the radio list, then one more row the respondent writes their own answer into. The "other" row is a radio in the same group as the options, so choosing it clears whichever option was picked -- and choosing an option clears it -- with no extra rule needed anywhere. Its label carries an id, because the text field beneath it is named by `aria-labelledby` pointing at that label rather than by a copy of the same words: the label is the author's, and a copy would drift the moment it renders markdown. The field cannot sit inside the label the way the radio does -- a text input inside a label takes the label's clicks -- which is why it is a sibling in its own indented div. One text field, not a list: this type takes a single written answer, where the checkbox flavour takes several and draws a row apiece. Class strings are inline rather than passed in, so this file can be diffed against the reference component side by side; a class string in a .py file is invisible to the stylesheet build, which scans templates and would drop the rules for it. The empty-comment separator lines exist only to suppress whitespace between literal elements; JSX discards that whitespace, so emitting it would break byte parity. See README. #}
