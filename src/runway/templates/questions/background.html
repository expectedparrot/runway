{# Stand-in for the questions a respondent is never shown. Compute, image generation and thinking-wrapped questions are answered on the server between pages and advanced straight past by the survey navigator, so no page for one is ever served. A third notice rather than one of the two in unsupported.html, because it is a third situation. The note there means "this package is behind"; the warning means "the survey needs fixing". Here nothing is wrong and nothing is missing: there is no control because there is no respondent. So it is informational blue, and it says what the question actually does instead of apologising for a control it will never have. The question text is drawn, in the same markup every other question's text is drawn in -- markdown rendered the same way, split into blocks around a file the same way. It is not something a respondent reads: it is a prompt for a model or an expression for the server. But it is the only part of one of these an author can get wrong, and checking that a generated image really asks for what they meant is exactly what they opened a preview to do. The notice sits directly beneath it and says who is answering, so nothing about the page claims to be one somebody is served. Omitted when the question carries none, rather than emitting the empty text div that markup would otherwise leave behind. #}
