{# Transcription of the reference implementation's checkbox-with-other question. The option rows are byte-identical to checkbox.html's, and duplicated here rather than shared, because the reference duplicates them: two components with their own copies of the loop. A shared partial would be a third thing neither of them has, and would hide the day the two drift apart — which the recorded goldens would catch and this file should not pre-empt. No Select all row. The wrapper the survey page mounts defaults `showSelectAll` to *false* here, the opposite of the plain checkbox's wrapper, so the row is never drawn — and `exclusive_options`, whose only effect on plain checkbox markup is to take that row away, therefore changes nothing here. The "other" block opens with exactly one empty row. Its remove button is rendered rather than omitted, so the inputs do not resize as rows come and go, but it is `invisible` and out of the tab order while it is the only row. The "Add another" button is held back until a row holds something, so an unanswered page — which is what a preview shows — has none. Class strings are inline rather than passed in, so this file can be diffed against the reference component side by side; a class string in a .py file is invisible to the stylesheet build, which scans templates and would drop the rules for it. The empty-comment separator lines exist only to suppress whitespace between literal elements; JSX discards that whitespace, so emitting it would break byte parity. See README. #}
