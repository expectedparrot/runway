{# Transcription of the reference implementation's checkbox question. Every row is a label wrapping the control, with an explicit `for` naming the input inside it -- the control is a span there, so the label cannot reach the input by containment alone. Ids are `{question_name}-{index}`, and there is no `name`: a checkbox group is not a radio group and the reference gives it none. The label span carries `grow` so a long option fills its row. The Select all row is the same control again under its own class, drawn last. Whether it appears is worked out in checkbox.py: it depends on the humanize schema, both on whether the box was asked for and on which options are exclusive, as well as on the option count. Class strings are inline rather than passed in, so this file can be diffed against the reference component side by side; a class string in a .py file is invisible to the stylesheet build, which scans templates and would drop the rules for it. The empty-comment separator lines exist only to suppress whitespace between literal elements; JSX discards that whitespace, so emitting it would break byte parity. See README. #}
